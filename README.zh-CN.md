# Canvas Node Align（白板里的文字对齐）

给白板的卡片正文、分组标签、连线标签、文件卡片标签加上文字对齐。

> **独立 Markdown 笔记正文的对齐不在这个插件里** —— 那是配套插件
> **[Note Text Align](https://github.com/jiangbianyan-gif/obsidian-note-text-align)** 的事
> （它写笔记的 frontmatter，机制和这里完全不同）。两个插件各管各的场合，互不干扰。

Canvas 原生**没有任何文字对齐设置**。右键菜单里的"对齐 / 分布"是**排列卡片**（把方块摆整齐），和"字往哪边靠"完全是两回事。本插件就是补这个空缺。

对齐有**两个方向**，互相独立，可任意组合：

| 方向 | 可选值 | 效果 |
|---|---|---|
| **水平** | 左对齐 / 居中 / 右对齐 | 每一行从哪里开始、到哪里结束 |
| **垂直** | 顶部 / 垂直居中 / 底部 | 整块正文落在卡片的哪个高度 |

3 × 3 = **9 种位置**。Canvas 原生只有「左对齐 + 顶部」这一种。

> 没有「两端对齐」：`text-align: justify` 只在**会折行的多行段落**里才有效果（按排版规范不拉伸最后一行），而卡片里的文字常是两三行短句、标签更是单行文字 —— 设了和左对齐一模一样。所以白板侧一律只有左 / 中 / 右。唯一例外是设置里的「卡片内嵌笔记的正文」：嵌进来的是真 Markdown，段落会折行，那一项保留两端对齐。

## 覆盖范围

| # | 文字在哪 | 方向 | 怎么设 | 存在哪 |
|---|---|---|---|---|
| 1 | 卡片正文（文本卡） | 水平 + 垂直 | 右键卡片，**逐张** | 卡片自己的文字里 |
| 2 | 卡片内嵌笔记的正文 | 水平 | 设置面板（全局） | 插件设置 |
| 3 | 卡片文件名标签 | 水平 | 右键卡片，**逐张** | 插件数据 |
| 4 | 分组标签 | 水平 | 右键分组，**逐组** | 插件数据 |
| 5 | 连线标签 | 水平 | 右键连线，**逐条** | 插件数据 |
| 6 | 卡片内的 callout / 标题 / 代码块 | 水平 | 跟随 #1 | — |
| 7 | 嵌入笔记 / 网页的卡片正文 | 垂直 | 右键卡片，**逐张** | 插件数据 |

**独立笔记**（单独打开的那种 .md）的对齐请用配套插件 **Note Text Align** —— 它管笔记自己打开时的正文，本插件管**笔记被嵌进卡片时**的那份正文（设置里的「卡片内嵌笔记的正文」）。

还附带一批命令：**一键把当前白板的全部卡片设成同一位置**（水平和垂直各有）。

> 标签那几项只有水平方向：它们是单行文字，高度贴着文字，没有可移动的余量。

## 安装

### 官方插件市场（推荐）
设置 → 第三方插件 → 浏览 → 搜索 **Canvas Node Align** → 安装 → 启用。

> 条目已通过 [community.obsidian.md](https://community.obsidian.md) 的自动审核。
> 若插件列表里一时搜不到，是目录还在刷新，用下面的手动方式即可。

### 手动
1. 从 Release 下载 `main.js`、`manifest.json`、`styles.css`
2. 放进 `<你的库>/.obsidian/plugins/canvas-node-align/`
3. 重启后到 设置 → 第三方插件 里启用

### BRAT
在 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 里添加 `jiangbianyan-gif/obsidian-canvas-node-align`。

### 环境要求
Obsidian **1.5.0** 及以上；开发与验证环境为 **1.13.7**。

## 用法

### 卡片正文（逐张）
右键卡片 → **文本对齐** → 鼠标移到这一项上（或直接点它），弹出 **3 × 3 九宫格**：

|  | 左 | 中 | 右 |
|---|---|---|---|
| **上** | 左上 | 上中 | 右上 |
| **中** | 左中 | **正中** | 右中 |
| **下** | 左下 | 下中 | 右下 |

下面还有两行：

- **居中** → 仅水平 / 仅垂直（只改一个方向，另一个原样不动）
- **清除**（两个方向一起回到默认）

合计 12 格，覆盖全部 9 种组合（3 水平 × 3 垂直）外加清除。每格画两条短线：
**横向**位置就是水平对齐、**纵向**位置就是垂直对齐，正中那格两条线都在正中间。
当前生效的那一格会高亮，面板上方的小字写着它叫什么（这张卡片没单独设过就是"跟随默认"）。

*「文本对齐」是插件加的菜单项，右键菜单里原有的那些（编辑 / 复制 / 删除…）一个不少地留着。*

两个方向互不干扰：设了"正中"之后再用"仅水平"改横向，垂直位置不会被打回顶部。

原理是在卡片第一行的末尾插一段普通文本标记：

```
模型变换<span class="cta-c"></span><span class="cta-vm"></span>
```

两个方向各有一套标记，两种写法都认：

| 方向 | 标记 | 标签写法 | 效果 |
|---|---|---|---|
| 水平 | `<span class="cta-l"></span>` | `#cta-l` | 左对齐 |
| 水平 | `<span class="cta-c"></span>` | `#cta-c` | 居中 |
| 水平 | `<span class="cta-r"></span>` | `#cta-r` | 右对齐 |
| 水平 | `<span class="cta-j"></span>` | `#cta-j` | 两端对齐（**已下架**，老文件里可能还有；见上） |
| 垂直 | `<span class="cta-vt"></span>` | `#cta-vt` | 顶部 |
| 垂直 | `<span class="cta-vm"></span>` | `#cta-vm` | 垂直居中 |
| 垂直 | `<span class="cta-vb"></span>` | `#cta-vb` | 底部 |

也可以**自己手写**——插件只是个方便的输入器。只写水平标记完全可以，垂直部分会跟随设置里的默认值。

标记一律加在**第一行末尾**，不能加在行首：行首插 HTML 会把 `- 列表`、`# 标题` 这类块级语法打断。

**插件对同一件事做两层处理**，这是它对「不污染 `.canvas` 格式」的兑现方式：

| 层 | 做什么 | 为什么要它 |
|---|---|---|
| **数据层** | 把标记写进卡片的文字 | 换电脑、临时禁用插件、只用一份 CSS 片段 —— 对齐都还在。`.canvas` 里除了这段纯文本，没有任何非标准字段 |
| **渲染层** | 运行时把 `cta-card-<对齐>` / `cta-v-<位置>` 类名挂到卡片元素上 | 让样式生效。刻意**不用 CSS 的 `has()` 伪类选器**，因为插件市场会把它判成性能警告；挂类名是更省的等价做法 |

手写标记同样有效：插件每次打开白板都会读一遍卡片文字，见到标记就补上类名。

### 垂直是怎么做到的
Obsidian 的卡片正文其实已经是一套纵向弹性布局：`.markdown-preview-view` 是 `flex-direction: column`，正文上下各有一个弹性占位块（`::before` / `::after`）夹着它。两个占位块被 `max-height: 16px` 卡死，剩余高度全被正文块吃掉 —— 所以文字**永远贴顶**。

本插件只是去调这两个占位块的伸缩：顶部 = 上方占位块不长；垂直居中 = 两个都解除上限、正文块也不再抢高度；底部 = 上方占位块吃满剩余高度。这一切都在 CSS 里完成，插件只负责挂类名。

> 内容比卡片高时，三种位置都会退回"贴顶 + 可滚动"，**不会丢字**。这也是刻意不用 `justify-content: center` 的原因 —— 那个做法在内容超高时会把上半截挤出可视区且滚不到。

### 分组 / 连线 / 文件名标签（逐项）
右键分组（或连线、或文件卡片）→ **…标签对齐** → 选对齐方式。

这三处**用不了文字标记**：Obsidian 是用 `setText()` / `textContent` 渲染它们的，塞 HTML 进去会原样显示出乱码。插件改成运行时给元素挂类名，并把选择记在自己的数据文件里。

**代价**：因为不写进 `.canvas`，禁用插件后这三项的对齐会失效。卡片正文（#1）没有这个问题。

### 嵌入笔记 / 网页的卡片（垂直，逐张）
右键这种卡片 → **卡片文字对齐 · 垂直**。

同样写不了标记 —— 卡片显示的是**别人的文件**，往里面插标记等于改那个文件。所以它的垂直位置也记在插件数据里。

### 整块白板统一
命令面板 →
- **整块白板：所有卡片水平居中**（另有左 / 右），**整块白板：所有卡片清除水平对齐**
- **整块白板：所有卡片垂直居中**（另有顶部 / 底部），**整块白板：所有卡片清除垂直对齐**

### 独立笔记的正文

**不在本插件里。** 那部分功能已迁到配套插件
**[Note Text Align](https://github.com/jiangbianyan-gif/obsidian-note-text-align)**：
在笔记里右键 →「笔记对齐」，或命令面板 →「笔记正文：…」。

本插件只负责下面这一种情况：

- **笔记被嵌进卡片时**（`![[笔记]]`）的正文对齐 → 设置里的「卡片内嵌笔记的正文」。

> 两边各管各的场合。以前（≤ 2.3.0）本插件也能改独立笔记，从 2.3.1 起交给上面那个插件 ——
> 它照样认老笔记里写过的 `cta-note-*` 类名，所以你已经设过的对齐不会失效。

### 设置
设置 → Canvas Node Align：

- **五个下拉**决定各处"没有单独设置过"时的默认**水平**对齐
  （其中「卡片内嵌笔记的正文」多一个「跟随卡片」选项）
- **卡片正文的默认垂直位置**决定没单独设置过垂直的卡片落在哪
- **最后一行也拉满**（两端对齐的补充开关，只作用于笔记正文）
- **清除所有单独设置**按钮

## 为什么不污染画布文件

不少 Canvas 增强插件会往 `.canvas` 里写私有字段（*Advanced JSON Canvas* 格式）。本插件刻意不这么做：

- **卡片正文**只写普通文本，`.canvas` 始终是标准 [JSON Canvas](https://jsoncanvas.org/)；换个工具打开，那串标记只是几个看不见的字符
- **分组 / 连线 / 文件名标签**的选择存在 `.obsidian/plugins/canvas-node-align/data.json`，完全不碰 `.canvas`
- 不往卡片的 `unknownData` 里塞东西；卸载插件后文件依旧合法可读

渲染效果全部由 CSS 负责（`styles.css`，或等价的 CSS 片段 `canvas-text-align.css`），插件本身不直接改 DOM 样式。

## 和 Advanced Canvas 的区别

[Advanced Canvas](https://github.com/developer-mike/obsidian-advanced-canvas) 的 **Node Styles** 里也带卡片文字对齐。想要整套功能（演示模式、节点形状、可折叠分组、节点模板、导出 PNG/SVG 等）就选它。

想要下面这些，选本插件：

- 只要对齐，不想捎带一大堆功能
- 卡片正文的对齐**在卸载插件后依然有效**
- `.canvas` 保持标准 JSON Canvas 格式，而不是私有格式

## 兼容性说明

插件用到了几处**不在官方 API 文档里**的 Canvas 内部接口：

| 用到 | 用途 |
|---|---|
| `canvas:node-menu` / `canvas:edge-menu` / `canvas:selection-menu` 事件 | 加右键菜单项 |
| `canvas.nodes`、`canvas.edges`、`canvas.selection` | 遍历与读取节点/连线 |
| `node.text` / `node.setText()` | 读写卡片文字 |
| `node.labelEl`、`edge.labelElement.textareaEl` | 给标签挂对齐类名 |
| `canvas.requestSave()` | 存盘并进入撤销历史 |

每一处都做了特性检测或回退，将来 Obsidian 改名的后果是"某个功能失灵"而不是"插件报错"。已在 Obsidian **1.13.7** 上验证。

`MenuItem.setSubmenu()` 同样做了检测：版本不支持时，对齐项会平铺进主菜单而不是收进子菜单。

## 已知限制

- 分组 / 连线 / 文件名标签、以及嵌入笔记卡片的垂直位置，在禁用插件后会失效（原因见上）
- 文件名标签的对齐要等标签比文字宽才看得见，所以 `styles.css` 给 `.canvas-node-label` 加了 `width: 100%`；副作用是超长文件名会被省略号截断
- 笔记正文在实时预览下对齐时，语法标记会跟着动；阅读视图更干净
- 对齐作用于卡片的**渲染态**。光标停在卡片里时是编辑态，该卡片会退回默认值——点一下白板空白处退出编辑即可看到效果。垂直方向**只在渲染态生效**（编辑时刻意不居中：打字时光标到处跳很难受）
- 白板侧**没有两端对齐**：`text-align: justify` 只拉伸"非最后一行"（排版规范），而卡片里常是两三行短句、标签更是单行文字，设了看不出差别。想要它就只在**笔记正文**里用；连最后一行也拉满的开关在设置里（同样只作用于笔记）
- 垂直居中/底部需要卡片**比文字高**才看得出来。卡片高度是自动贴合文字的，先手动把卡片拉高一点

## 开发

```
main.js                       插件源码（ES2017，无打包器、无依赖）
styles.css                    全部渲染规则
manifest.json                 插件清单
versions.json                 版本 → 最低主程序版本
test/align.test.js            纯函数单测
tools/build.mjs               生产构建（npm run build）
tools/set-author.mjs          一次性替换作者与 GitHub 占位符
tools/check-manifest.mjs      按官方规则校验清单字段
tools/install.sh              把插件装进指定库，方便本地测试
docs/SUBMISSION.md            发版与提交市场的完整清单
.github/workflows/release.yml 打 tag 时自动建 Release
```

没有打包流程，`main.js` 手写后直接被加载，运行时与构建期都没有依赖。

```bash
npm run build                   # 校验发布产物 —— 市场扫描跑的就是这条
npm run build -- --zip          # 顺带产出 dist/canvas-node-align-<版本>.zip
npm run verify                  # 构建 + 单测
tools/install.sh "/库的路径"
```

**既然不需要编译，为什么还要有构建脚本。** 社区目录会按 `build` → `build:plugin` → `compile` 的顺序取**找到的第一个**脚本跑一遍，再拿结果和仓库里已提交的源码比对，以此确认「发布出来的东西确实是从这个仓库构建的」。三者都没有时，它就报「构建验证无法运行」。所以 `npm run build` 做的是：在进程内解析 `main.js`、校验元数据、检查 Obsidian 要下载的三个文件齐全且没有 BOM，并打印它们的大小与 sha256，方便和 Release 资产逐一对上。它**刻意不重写任何已提交文件** —— 连跑两次哈希完全一致，而这正是目录在检查的那个性质。

单测的做法是**从 `main.js` 里切出纯函数再用 `new Function` 执行**，测的就是实际发布的那份代码。116 条断言覆盖两个方向的标记读写、幂等替换、清除、**「设一个方向不会抹掉另一个方向」**、列表/标题语法安全、Windows 换行、类名清理（含两个前缀互不误伤）、frontmatter 合并，以及一把 CSS 守卫：垂直选择器一旦丢了足够的权重就直接让测试失败。

源码注释为中文。

## 发版与提交

改版本要同时动三处（`manifest.json`、`versions.json`、git tag），**tag 必须与 manifest 里的版本完全一致**，否则 Obsidian 装不上。完整清单见 `docs/SUBMISSION.md`，里面也写了当前社区目录的提交流程。
